# dots プロジェクト背景および v0.1.0 仕様設計書

## 文書情報

- 対象バージョン: v0.1.0
- 実装言語: Go 1.21 以上
- 設定ファイル: dots.toml

## 1. プロジェクト背景と目的

dots は、軽量で宣言的なクロスプラットフォームの dotfiles 管理CLIである。TOMLでソースと配置先を宣言し、シンボリックリンクの作成・更新・診断に機能を絞る。

GNU Stow のようにリポジトリ構造と配置先が固定される方式では、OSごとに異なる配置先を扱いにくい。一方、高機能なdotfiles管理ツールは、独自テンプレートや環境依存の仕組みによって学習・運用負荷が増える。dots はOS別の配置先を設定ファイルで表現しつつ、管理対象の配置に特化する。

### 設計方針

1. 短く直感的な宣言型設定
2. dotfilesリポジトリ構造の柔軟性
3. Windows、macOS、Linux、FreeBSDのサポート
4. 分かりやすく、見やすいCLI体験

### v0.1.0 の非目標

- パッケージマネージャー
- シェル環境変数の管理
- Nixの代替
- テンプレートエンジン
- Gitリポジトリの自動取得
- プロファイル切り替え

## 2. システム要件と主要ライブラリ

- Go 1.21 以上
- CLI: github.com/spf13/cobra
- TOML: github.com/pelletier/go-toml/v2
- ファイルシステム抽象化: 内部の fs.Manager インターフェース
- テスト用ファイルシステム: github.com/go-git/go-billy/v5 の memfs
- 対話UI: github.com/charmbracelet/huh
- 再帰glob: slash区切りパスと ** に対応するパターン照合実装 github.com/bmatcuk/doublestar/v4

本番のファイルシステム操作は os 標準パッケージをラップした fs.Manager を使用する。テストでは memfs を注入する。実OSのシンボリックリンク権限・ドライブ構成・パス規則は、対象OS上の統合確認で扱う。

## 3. CLIコマンド

| コマンド | 動作 |
| --- | --- |
| dots init | カレントディレクトリに dots.toml の雛形を作成する。既存ファイルは上書きせずエラーにする。 |
| dots doctor | 設定とファイルシステムを比較し、リンク状態と競合を表示する。 |
| dots apply | 設定に基づいてシンボリックリンクを作成・更新する。競合を対話的に解決する。 |
| dots apply --dry-run | 変更を行わず、作成・スキップ・バックアップ付き置換・エラーのPlanを表示する。 |
| dots restore <archive> | dots が作成したバックアップを、記録された元の配置先へ復元する。 |
| dots restore <archive> --dry-run | 変更を行わず、復元先と競合の有無を表示する。 |
| dots edit | 見つかった dots.toml を環境変数 EDITOR で開く。 |
| dots --version | インストール済みバージョンを表示する。 |

### 設定ファイルの発見

dots init はカレントディレクトリに dots.toml を作る。doctor、apply、restore、edit はカレントディレクトリから親ディレクトリへ順に探し、最初に見つかった dots.toml を使う。そのファイルが置かれているディレクトリをリポジトリルートとする。見つからない場合はエラーにする。

## 4. パス解決

### source

source は dots.toml のあるリポジトリルートを基準に解決する。設定中の source はリポジトリルートからの相対パスとする。

### target

target の設定文字列には絶対パスを許可しない。Unix形式の / で始まるパス、Windowsのドライブ指定パス、UNCパスはエラーにする。

- 通常の相対パスはリポジトリルートを基準にする。
- 相対パスを正規化した結果、.. によってリポジトリルートの外へ出る場合はエラーにする。
- ~ または ~/ で始まるパスはユーザーのホームディレクトリを基準にする。
- ~user、$HOME、その他の環境変数展開は許可しない。
- TOML内の設定パスとignoreパターンは、OS間で一貫させるため / 区切りで記述する。実行時にOS形式へ変換する。

パスを正規化・展開した後の実行時パスは、OSのファイルシステム操作に渡す絶対パスとなる。設定ファイルに絶対パスを書くことは禁止する。

## 5. 設定ファイルのスキーマ

2種類の記法をサポートする。OS名は Go の実行環境名を使う。v0.1.0で特別に扱うOS名は darwin、windows、linux、freebsd とする。

### 5.1 フラット記法

キーは配置先、値はソースである。dots.<os> は現在のOSで有効な追加・上書きテーブルである。

    [dots]
    "~/.vim" = "config/vim"
    "~/.vimrc" = "vimrc"

    [dots.darwin]
    "~/.config/karabiner" = "config/darwin/karabiner"

同じ解決済み配置先に共通設定と現在OSの設定がある場合、OS固有設定を採用する。異なる配置先の設定は両方有効となる。

### 5.2 自動配置記法

auto はルールグループの配列である。各グループは共通ルールを持てる。直後に記述する [[auto.<os>]] は、その直前の [[auto]] グループに属するOS固有ルールである。TOMLの配列テーブルの規則により、OS固有ルールは直近に定義されたauto要素へ所属する。

各ルールはsource、targetを持ち、ignoreは省略時に空とする。共通sourceとOS固有sourceは別々に走査し、展開後に配置先単位で統合する。OS固有ルールは同じ配置先に出力する共通ファイルだけを置き換える。共通側にしかないファイルは残す。

    [[auto]]
    source = "config/auto"
    target = "~/.config"
    ignore = ["README.md", ".DS_Store"]

    [[auto.darwin]]
    source = "config/darwin-auto"
    target = "~/.config"
    ignore = ["**/README.md", "**/.DS_Store"]

OS固有ルールだけを持つグループは、空の親配列テーブルを置いて定義できる。

    [[auto]]

    [[auto.darwin]]
    source = "config/darwin-only"
    target = "~/.config"

### 5.3 auto の再帰展開

1. source以下を再帰的に走査する。
2. sourceからの相対パスを保持してtarget以下に同じディレクトリ構造を作る。
3. 通常ファイルごとにtarget側の親ディレクトリを実ディレクトリとして作成し、ファイルのシンボリックリンクを作る。
4. 空のsourceディレクトリは、そのディレクトリ自体へのシンボリックリンクを作る。
5. ignoreに一致したファイルやディレクトリは配置しない。ディレクトリに一致した場合、その配下を走査しない。ignoreされた項目によって空になったディレクトリは、sourceが物理的に空でない限り、実ディレクトリとして扱う。
6. source内のシンボリックリンクは末端項目として扱い、リンク先をたどって走査しない。配置先リンクはsource内のリンク項目を指す。リンク切れまたは循環するsourceシンボリックリンクは、apply前の検証エラーとする。
7. source内に通常ファイル、ディレクトリ、シンボリックリンク以外の項目があればエラーとする。

#### ignore パターン

ignoreパターンはsourceルートからの相対パスに照合し、区切り文字は / とする。パターン比較は全OSで大文字・小文字を区別する。

- README.md はsource直下のREADME.mdだけに一致する。
- **/README.md は直下を含むすべての階層のREADME.mdに一致する。
- * は1つのパス要素内に一致し、/ をまたがない。
- ** はパス要素全体として使い、0個以上のディレクトリ要素に一致する。したがって **/README.md は直下にも一致する。
- 不正なパターンは設定エラーとする。

### 5.4 ルールの優先順位と重複

優先順位は次の高い順とする。

    dots.<os> > dots > auto.<os> > auto

各ルールを実際の配置先へ展開した後、パスを正規化して重複を検査する。同じ配置先に複数候補がある場合、最上位の候補を採用する。同じ優先順位の候補が複数ある場合は設定エラーとし、apply開始前に停止する。下位候補は適用せず、doctorとPlanでは上書きされたことを表示する。

この優先順位は記法をまたいで適用する。たとえば共通dotsの出力先とauto.darwinの出力先が同じ場合は共通dotsを採用する。OS固有autoファイルが共通autoファイルと同じ出力先になる場合はOS固有ファイルを採用し、他の共通ファイルは残す。

同じ出力先に加え、シンボリックリンクや通常ファイルとなるターゲットの下に別のターゲットを配置するなど、親子パス構造が衝突するルールもapply前にエラーとする。

## 6. 状態評価とapply

doctorとapplyは各有効ルールのsourceとtargetを検証する。sourceが存在しない、sourceのシンボリックリンクがリンク切れまたは循環している、相対シンボリックリンクを作れない場合は、変更前の検証エラーとする。

ターゲット判定にはLstatを使い、リンク先をたどらずターゲット自体を調べる。

| 状態 | 条件 | applyでの動作 |
| --- | --- | --- |
| NotExist | ターゲットが存在しない | 親ディレクトリを作成し、シンボリックリンクを作成する |
| ValidLink | ターゲットが期待するsource項目を指すシンボリックリンク | Skip |
| InvalidLink | 別のsource項目を指すリンク、またはリンク切れのターゲットリンク | バックアップ付き置換の確認 |
| FileOrDir | 通常ファイルまたはディレクトリが存在する | バックアップ付き置換の確認 |

ValidLinkの判定ではLstatとReadlinkを使う。Readlinkが相対パスを返した場合はターゲットの親ディレクトリを基準に解決し、正規化したパスが設定上のsource項目を指すか比較する。source自体がシンボリックリンクの場合、そのリンク項目を比較対象とし、リンク先まで解決して比較しない。

targetの親ディレクトリが存在しない場合は自動作成する。親に通常ファイルやシンボリックリンクがあり、安全に配置できない場合はエラーにする。ターゲットが壊れたシンボリックリンクでも、Lstatでリンクとして検出するためNotExistとは扱わない。

### 相対シンボリックリンク

作成するシンボリックリンクのリンク先は、source項目を指す相対パスとする。相対パスはsourceとtargetの実行時パスを解決した後に計算する。sourceとtargetが異なるボリュームにあるWindows環境では相対リンクを作れないため、apply前にエラーにする。絶対リンク、コピー、ジャンクションへのフォールバックは行わない。

WindowsでOS権限またはDeveloper Modeの制約によりリンク作成が拒否された場合は、エラーと原因の案内を表示する。リンク以外の方式へ自動切り替えない。

### 競合時の対話

競合時の選択肢は、バックアップして置き換える、またはスキップする。

- Yes: 今回のターゲットをバックアップして置き換える。
- Yes + Yes to All: 今回および以降の競合をバックアップして置き換える。
- No: 今回のターゲットをスキップする。
- No + No to All: 今回および以降の競合をスキップする。

TTYがなく、対話が必要な競合がPlanに含まれる場合は、変更を始める前にエラー終了する。dry-runでは対話を表示せず、競合と想定動作をPlanに記載する。

applyは正規化したターゲットパスの辞書順でPlanを処理する。検証エラーは変更前に検出する。実行中に予期しないI/Oエラーが起きた場合、すでに完了した変更はロールバックせず、部分適用として残りの状態と失敗箇所を報告する。

## 7. バックアップと復元

### 7.1 バックアップ

既存ターゲットを置き換える前に、必ずアーカイブを作成する。削除だけを行う選択肢は設けない。

保存先:

- Linux、FreeBSDなど: 有効なXDG_DATA_HOME/dots/backups。XDG_DATA_HOMEが未設定または空なら~/.local/share/dots/backups。設定されているが絶対パスでない場合はエラーにする。
- macOS: ~/Library/Application Support/dots/backups
- Windows: %LOCALAPPDATA%\dots\backups

形式は全OS共通でgzip圧縮tarとする。競合ターゲットごとに1つのアーカイブを作る。UTC日時と一意な連番をファイル名に使い、自動削除しない。バックアップディレクトリとアーカイブは、対応OSで現在のユーザーだけがアクセスできる権限で作成する。

アーカイブはmanifest.jsonとpayloadを含む。マニフェストには形式バージョン、元の実行時ターゲットパス、作成日時、対象種別を記録する。payloadの各エントリー名は相対パスとし、絶対パスや..を含めない。

- 通常ファイルの内容、ディレクトリ構造、更新日時、対応可能なアクセス権情報を保存する。
- シンボリックリンクはリンク先をたどらず、リンク文字列自体を保存する。リンク切れの既存ターゲットリンクも保存できる。
- 所有者情報、ACL、代替データストリームなどOS固有の情報は保証しない。
- 通常ファイル、ディレクトリ、シンボリックリンク以外をバックアップ対象で検出した場合は置き換えない。

バックアップの一時ファイルを書き終えてtarとgzipのクローズが成功した後に、最終名へ確定する。バックアップに失敗した場合は元ターゲットを変更しない。アーカイブ確定後、元ターゲットを同じ親ディレクトリ内に一時退避してリンクを作成する。成功時は退避データを削除する。失敗時は元ターゲットを戻し、復旧できない場合は退避先とアーカイブの両方を表示する。

### 7.2 restore

    dots restore <archive>
    dots restore <archive> --dry-run

restoreはdots形式の対応済みマニフェストを持つgzip圧縮tarだけを受け入れ、マニフェストに記録された元の配置先へ復元する。v0.1.0では別の復元先を指定する機能を設けない。

復元先が存在しない場合は復元する。復元先に既存ファイル、ディレクトリ、またはシンボリックリンクがある場合は、「現在の内容をバックアップして復元」または「スキップ」を確認する。バックアップが成功してから復元に進む。

復元前にマニフェストと全アーカイブ項目を検証する。絶対パス、..、payload外に出るパス、重複項目、対応外のファイル種別、壊れたアーカイブは拒否する。展開中にアーカイブ内のシンボリックリンクをたどらない。復元データは一時領域で検証してから配置する。配置に失敗した場合は、置き換え前のターゲットを戻す。復旧にも失敗した場合は、退避データとアーカイブの場所を表示する。

restore --dry-runは復元先、アーカイブの対象種別、競合の有無、予定するバックアップ・復元動作を表示し、ファイルシステムを変更しない。TTYなしで既存ターゲットとの競合がある場合は変更前にエラー終了する。

## 8. doctor、表示、終了

doctorは設定の妥当性、sourceの存在、相対リンクの実現可否、ターゲット状態、上書き・重複ルールを一覧表示する。doctorはファイルシステムを変更しない。

- 設定またはI/Oのエラーは非ゼロ終了とする。
- doctorはNotExist、InvalidLink、FileOrDirなどNot OKの状態を検出した場合に非ゼロ終了とする。
- applyでユーザーが明示的にスキップした競合はエラーではなく、スキップ件数として報告する。
- apply/restoreで予期しない処理エラーがあった場合は非ゼロ終了し、部分適用または復旧状況を表示する。

## 9. テスト方針

fs.Managerを通じてOSアクセスを差し替え、memfsを用いてパス解決、状態評価、優先順位、ignore、バックアップ計画の単体検証を行う。memfsは実OSのシンボリックリンク権限・Windowsのボリューム制約を再現しないため、Windows、macOS、Linux、FreeBSD上でOS固有のリンク動作も確認する。
